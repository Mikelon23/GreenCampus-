# Database Schema

GreenCampus+ Platform

## 1. Overview

The GreenCampus+ database is designed to store environmental data, user interactions, sustainability indicators, and innovation activities.

The system uses PostgreSQL as the relational database engine.

The schema is organized into five main data domains:

1. User Management
2. Environmental Monitoring
3. Sustainability Analytics
4. Gamification System
5. Innovation and Hackathon Management

Each domain corresponds to one or more tables that support the platform's core functionality.

---

# 2. User Management

## users

Stores user accounts and authentication information.

Fields:

id
name
email
role
created_at

Roles may include:

student
admin
researcher

---

# 3. Campus Structure

## campus_zones

Represents physical areas of the university campus.

Examples:

library
engineering_building
cafeteria
green_areas

Fields:

id
name
description
location_coordinates

Environmental data can be associated with specific campus zones.

---

# 4. Environmental Monitoring

## sensor_data

Stores environmental readings from sensors or simulated sources.

Fields:

id
zone_id
temperature
humidity
co2_level
energy_usage
timestamp

Relationship:

zone_id → campus_zones.id

This table supports environmental dashboards and sustainability analytics.

---

# 5. Sustainability Indicators

## sustainability_scores

Stores calculated sustainability indicators for the campus.

Fields:

id
zone_id
sustainability_score
energy_efficiency_index
carbon_index
calculated_at

Relationship:

zone_id → campus_zones.id

These indicators are generated by the Sustainability Engine.

---

# 6. Carbon Footprint Tracking

## carbon_footprint

Tracks carbon footprint estimates associated with users or campus activities.

Fields:

id
user_id
activity_type
carbon_emission_estimate
recorded_at

Relationship:

user_id → users.id

Activity examples:

transportation
energy_usage
waste_generation

This table supports personal and institutional carbon impact analysis.

---

# 7. Eco-Actions

## eco_actions

Records sustainability activities performed by users.

Examples:

planting trees
participating in clean-up events
recycling initiatives
public transport usage

Fields:

id
user_id
action_type
points_awarded
timestamp

Relationship:

user_id → users.id

These actions feed the gamification system.

---

# 8. Gamification System

## green_points

Stores accumulated sustainability points for users.

Fields:

id
user_id
total_points
last_updated

Relationship:

user_id → users.id

---

## badges

Defines sustainability achievement badges.

Fields:

id
badge_name
description
points_required

---

## user_badges

Associates badges with users.

Fields:

id
user_id
badge_id
earned_at

Relationships:

user_id → users.id
badge_id → badges.id

---

# 9. Innovation and Hackathons

## hackathons

Stores sustainability challenge events.

Fields:

id
title
description
start_date
end_date
status

Status examples:

upcoming
active
completed

---

## teams

Represents teams participating in hackathons.

Fields:

id
team_name
hackathon_id
created_at

Relationship:

hackathon_id → hackathons.id

---

## team_members

Associates users with teams.

Fields:

id
team_id
user_id

Relationships:

team_id → teams.id
user_id → users.id

---

## projects

Stores project submissions for hackathons.

Fields:

id
team_id
title
description
submission_date
impact_score

Relationship:

team_id → teams.id

Projects may include sustainability solutions developed by students.

---

# 10. Tree Planting Initiatives

## trees_planted

Tracks tree planting activities associated with sustainability campaigns.

Fields:

id
user_id
zone_id
tree_species
planting_date

Relationships:

user_id → users.id
zone_id → campus_zones.id

This table helps quantify environmental impact.

---

# 11. Key Relationships

Important relationships across the database include:

users → eco_actions
users → carbon_footprint
users → green_points
users → user_badges

campus_zones → sensor_data
campus_zones → sustainability_scores
campus_zones → trees_planted

hackathons → teams
teams → team_members
teams → projects

These relationships enable integrated analytics across the platform.

---

# 12. Data Integrity

The database design enforces the following principles:

Primary keys for all tables
Foreign key relationships between entities
Consistent timestamp fields for tracking events
Normalized structure to avoid data redundancy

Indexes may be added for frequently queried fields such as:

user_id
zone_id
timestamp

---

# 13. Future Extensions

The schema allows future extensions including:

IoT device management

Advanced sustainability metrics
Integration with university infrastructure systems
