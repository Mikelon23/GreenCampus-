# GreenCampus+

GreenCampus+ is a sustainability intelligence platform for universities. It combines environmental monitoring (IoT-like sensor readings), zone-level sustainability analytics, carbon tracking, hackathon project submissions, and a gamified "Eco Forest" loop (energy drops, streaks, tree growth, social interactions, and campus-wide goals).

## Architecture Overview

- **Frontend**: Next.js (React) on port `3000`
- **Backend**: FastAPI on port `8000`
- **Database**: PostgreSQL (persistent volume)
- **Simulator (optional)**: Python script that continuously posts sensor readings to the backend

At a high level:
- The frontend calls the backend REST API (`/api/*`).
- The backend persists data in PostgreSQL via SQLAlchemy and manages schema changes via Alembic migrations.
- The simulator can be used to generate realistic sensor traffic.

## Tech Stack

- Frontend: Next.js 14, React 18, Tailwind CSS
- Backend: FastAPI, SQLAlchemy, Alembic, Pydantic
- Database: PostgreSQL
- Auth: JWT (Bearer tokens)
- Containers: Docker + Docker Compose

## Key Features

- **Campus zones**: manage and view campus zones and metadata
- **Sensor ingestion**: POST sensor readings (simulator-friendly)
- **Sustainability analytics**: zone scores and indicators
- **Carbon tracker**: users can create/update/delete their records (editable for 30 minutes)
- **Eco-actions & points**: log eco-actions, earn points, badges, leaderboard (actions editable for 30 minutes)
- **Hackathons**: create teams, submit projects, upload attachments (projects editable for 30 minutes)
- **Eco Forest (gamification)**:
  - collectable energy drops generated by actions and projects
  - daily streaks and progression
  - virtual tree growth stages
  - social interaction (help/rescue energy)
  - collective campus goals
- **Admin CRUD**: admin-only CRUD editor for multiple modules

## Setup Instructions

### Option 1 - Docker (Recommended)

Prerequisites:
- Docker Desktop (includes Docker Compose v2)

1. Create a local `.env` file:
   - Copy `.env.example` to `.env` and adjust if needed.
2. Start everything:
   - Linux/Mac: `./scripts/start.sh`
   - Windows (PowerShell): `./scripts/start.ps1`

Alternatively (advanced):
- `docker compose up --build`
  - This starts Postgres, runs migrations + seed via `backend-init`, then starts backend and frontend.

Access:
- Frontend: `http://localhost:3000`
- Backend: `http://localhost:8000`
- Swagger UI: `http://localhost:8000/docs`

Stop:
- `docker compose down`
  - Add `-v` to remove the Postgres volume (will delete all data).

### Option 2 - Manual Setup (No Docker)

Prerequisites:
- Python 3.12+
- Node.js 20+
- PostgreSQL 16+

1. Backend
   1. Create env file:
      - Copy `backend/.env.example` to `backend/.env` and update `DATABASE_URL` and `JWT_SECRET`.
   2. Install:
      - `pip install -r backend/requirements.txt`
   3. Migrations:
      - `alembic -c backend/alembic.ini upgrade head`
   4. Seed:
      - `python -m backend.seed`
   5. Run:
      - `uvicorn backend.main:app --reload --host 127.0.0.1 --port 8000`

2. Frontend
   1. Create env file:
      - Copy `frontend/.env.example` to `frontend/.env.local`
   2. Install:
      - `npm install`
   3. Run:
      - `npm run dev`

Frontend URL: `http://localhost:3000`

## Usage

### Login

Default seeded admin (configurable via `.env` for Docker):
- Email: `admin@campus.edu`
- Password: `admin1234`

You can also register a new user from the UI (`/register`).

### Simulator

Manual:
- Configure `simulation/.env` (optional) and run:
  - `python simulation/simulator.py`

Docker (optional service):
- Start the simulator profile:
  - `docker compose --profile simulator up -d simulator`

Notes:
- `/api/sensors` requires authentication. The simulator needs `SIM_AUTH_TOKEN` (a JWT from `/api/auth/login`) unless you modify the backend policy.

### Quick API Checks

- Health:
  - `GET http://localhost:8000/health`
- Swagger:
  - `http://localhost:8000/docs`

## Troubleshooting

### NetworkError / Fetch Failed in the Browser

- Confirm backend is reachable:
  - `http://localhost:8000/health`
- Confirm frontend is using the correct API base:
  - Check `NEXT_PUBLIC_API_BASE_URL` in `.env` (Docker) or `frontend/.env.local` (manual).

### Database Not Connected

- Docker:
  - `docker compose ps`
  - `docker compose logs db`
- Manual:
  - Ensure Postgres is running and `DATABASE_URL` points to the correct host/port/database.

### Migrations Not Applied

- Docker:
  - Re-run init:
    - `docker compose up --no-deps --abort-on-container-exit backend-init`
- Manual:
  - `alembic -c backend/alembic.ini upgrade head`

### CORS Issues

- The backend currently allows origins for `http://localhost:3000` and `http://127.0.0.1:3000`.
- If you run the frontend on a different origin, update CORS settings in `backend/main.py`.
